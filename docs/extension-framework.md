# 受约束节点扩展框架基线

> 状态：2026-08-20 已确认的当前优先开发阶段。本文定义“开放扩展框架”的完成标准；在这些标准满足前，现有注册表只能称为源码级静态扩展点。

## 1. 目标

扩展框架允许外部开发者在不修改应用源码、不重新编译主程序的情况下，为节点增加新的本地展示、校验、派生结果和用户主动触发的处理动作。

扩展的是“信息的使用方式”，不是信息的核心模型。无论安装什么扩展，正式数据仍然只有：

```text
Node
  id
  name
  content

Reference
  source_node_id
  target_node_id
```

扩展不得注册新的节点字段、关系类型或业务对象，也不得改变名称唯一、引用端点存在、原子保存、撤销、加密、历史和备份等不变量。

## 2. 当前状态与术语

当前 `ContentProcessorRegistry`、`ContentMarkerRegistry` 和展示注册表仍属于源码级静态扩展点：仓库贡献者可以增加内置功能，但必须修改源码并重新构建。工作区 v3 已有通用扩展元数据命名空间，内置 JSON 检查器已经通过受限快照、声明式展示和命名空间元数据宿主工作；独立 Wasmtime 子进程、轻量 IPC、能力复验、资源限制和锁定终止底座也已进入源码。由于安装/授权/启停生命周期、修改提案接入和稳定 SDK 尚未完成，用户仍不能安装第三方扩展。

本文使用以下术语：

- **扩展 API**：应用允许扩展调用的版本化契约。
- **扩展 SDK**：把契约映射到具体开发语言的类型、构建工具和测试工具。
- **扩展包**：可以独立安装的 `.liext` 文件。
- **扩展元数据**：只影响扩展展示或操作偏好的小型持久状态，不表达节点之间的关系。
- **派生数据**：可以从正式节点重新计算的缓存或运行结果，不进入工作区。
- **修改提案**：扩展建议应用执行的正式数据操作；扩展自身没有直接写权限。

## 3. 不可破坏的边界

### 3.1 Reference 是唯一跨节点语义关系

扩展元数据不能保存稳定节点 ID、节点路径或其他可持久恢复的跨节点指针。脚本依赖另一个脚本、优惠码适用于某服务、账号注册了某服务等关系必须创建正式 `Reference`，不能藏在扩展私有数据中。这个边界由宿主不提供稳定节点标识来保证，不根据 `parentNode`、`referenceStyle` 一类普通字段名猜测语义；字段名过滤既会误伤正常设置，也无法识别换名后的隐藏关系。

扩展读取图时只获得本次调用有效的无意义 `NodeHandle`。句柄在调用结束、锁定、工作区替换或授权代次变化后立即失效，不能写入扩展元数据。扩展提出建立引用时使用句柄，由宿主映射到当前节点 ID 并重新验证端点。

判断规则：移除扩展后仍需要被用户理解的信息，必须留在节点正文或 `Reference`；只有丢失后不影响信息含义的显示和操作偏好才允许成为扩展元数据。

### 3.2 扩展不能直接修改正式数据

扩展不能访问工作区文件、数据库或持久化对象。需要修改节点、引用或布局时只能返回 `ChangeProposal`：

```text
ChangeProposal
  base_revision
  title_key
  operations[]
```

宿主必须按当前工作区重新校验名称、端点、容量和授权代次，生成差异预览，并把用户确认后的全部操作作为一个历史事务和一次持久化提交执行。取消、过期、扩展崩溃或任一步失败都不得留下部分修改。

节点名称和正文仍是可为空字符串，不是可空字段。更新操作使用显式 `unchanged | set(value)` 补丁；只有 `set("")` 表示清空，扩展没有读取权限或不想修改某字段时必须返回 `unchanged`。创建节点则始终提供名称和正文字符串，避免宿主猜测 `none` 的含义。

第一版允许的正式操作只有：创建普通节点、在单节点动作中修改当前节点名称或正文、建立或移除正式引用。多选动作没有隐含“当前节点”，因此不能返回 `update-current-node` 或节点级元数据；将来若需要批量更新，必须新增带临时句柄目标且可逐项预览的版本化操作。删除节点、替换工作区、修改加密与备份配置、读取或写入布局不向第三方扩展开放。

### 3.3 扩展缺失不能损坏信息

停用、卸载或升级失败时：

- 节点名称、正文和引用保持可读。
- 未识别的处理器 ID 与扩展元数据原样保留。
- 节点安全降级为纯文本展示。
- 默认卸载只删除扩展程序，不删除元数据；清除元数据是独立确认操作。
- 重新安装兼容版本后可以继续读取保留的元数据。

## 4. 扩展可见的数据

扩展通过宿主生成的只读快照工作，不接触 React 状态、Rust 领域对象或完整工作区文件。

```text
NodeSnapshotV1
  handle
  name
  content
  direct_outgoing_handles[]   仅 graph.read.direct 授权后出现
  direct_incoming_handles[]   仅 graph.read.direct 授权后出现
```

规则：

- `handle` 只在一次调用内有效，不是节点 ID。
- 默认只提供当前节点，不提供全库枚举和搜索。
- 名称和正文分别需要 `node.read.name`、`node.read.content`。
- 直接引用需要 `graph.read.direct`；第一版不提供递归图遍历。
- 布局属于具体视图，第一版第三方 API 完全不提供布局读取或修改。
- 被标记为 `secret`、`totp` 或旧式 TOTP 的 payload 在生成快照前由宿主剥离；第一版第三方扩展不能申请原始秘密读取权限。
- 未标记的普通正文不会被应用猜测为秘密；安装和启用 `node.read.content` 扩展时必须明确提示它能够看到用户交给它处理的普通正文。

## 5. 扩展元数据

工作区下一版本增加受核心校验的扩展元数据容器：

```text
view.extensionMetadata[extension_id]
  schema_version
  workspace
  by_node_id[node_id]
```

其中 `node_id` 只存在于宿主维护的外层索引，扩展读写当前节点记录时不接触这个 ID。

### 5.1 允许保存的内容

- 显示行号、自动换行、折叠层级等展示偏好。
- 扩展定义的枚举模式、有界数字和短文本配置。
- 只影响扩展自身行为、删除后不损坏信息含义的状态。

禁止保存：

- 其他节点的 ID、名称副本或隐藏关系。
- 节点正文、秘密 payload、脚本输出或模型响应副本。
- 文件路径、访问令牌、环境变量、网络凭据。
- 可以重新计算的大型缓存、索引或向量。

### 5.2 格式与容量

- 扩展包必须提供受限 JSON Schema，使用 `additionalProperties: false`。
- 元数据只允许 JSON 标量、数组和对象，不允许二进制。
- 字符串和数组必须声明上限；数字必须同时声明最小值和最大值，或使用有限 `enum` / `const`。为保证 Rust、Wasm 和 JavaScript 对签名 Schema 得到相同结果，数值的绝对值不得超过 JSON/JavaScript 可精确表示的最大整数 `2^53-1`。Schema 中的 `default` 必须满足类型、枚举、长度、数量、必填字段和数值范围等全部已声明约束。
- 一个工作区最多保留 256 个扩展命名空间；通用边界限制对象最多 128 个属性、数组最多 1,024 项、字符串最多 4,096 个 Unicode 标量值和 JSON 深度最多 16。
- 单节点单扩展记录最多 16 KiB。
- 单扩展工作区级记录最多 64 KiB。
- 单个扩展在一个工作区内最多 4 MiB。
- 全部扩展元数据合计最多 16 MiB。
- JSON 最大深度 16，单个字符串最多 4,096 个 Unicode 标量值。

核心始终验证外层结构和容量；已安装扩展的 payload 还要通过该扩展声明的 Schema。未知扩展的 payload 在满足通用容量和 JSON 边界时原样保留，不能因为缺少扩展而删除。

### 5.3 版本与迁移

元数据记录独立的 `schema_version`。扩展升级需要迁移时，宿主把旧元数据副本交给新版本迁移入口，在隔离运行时完成后按新 Schema 验证，再以一次工作区事务替换。失败、超时或取消保留旧版本和旧元数据，不允许部分迁移。

## 6. 能力与授权

第一版扩展清单可以申请：

| 能力 | 含义 |
|---|---|
| `node.read.name` | 读取用户交给本次调用的节点名称 |
| `node.read.content` | 读取已经剥离已知秘密标记的正文 |
| `graph.read.direct` | 读取当前授权范围内的直接引用句柄 |
| `metadata.node.read` | 读取当前节点下本扩展自己的元数据 |
| `metadata.node.write` | 写入当前节点下本扩展自己的元数据 |
| `metadata.workspace.read` | 读取本扩展自己的工作区级设置 |
| `metadata.workspace.write` | 写入本扩展自己的工作区级设置 |
| `workspace.propose` | 返回需要用户确认的正式数据修改提案 |
| `clock.monotonic` | 读取宿主提供的单调时间，不获得系统时区或用户信息 |

以下能力不在第一版第三方 API 中：原始秘密、剪贴板、任意文件、网络、环境变量、子进程、系统凭据、后台常驻任务、启动时自动执行、布局和远端 AI。

安装时展示完整能力清单；新增能力的升级必须重新授权。停用扩展立即撤销能力并停止运行时。工作区锁定、会话锁定、休眠、应用退出或数据密钥轮换时，宿主先推进授权代次，再终止全部扩展进程并丢弃迟到结果。

## 7. 展示与交互

第三方扩展不能向 WebView 注入 JavaScript、HTML、CSS 或 React 组件，只能返回版本化的声明式展示树。第一版控件限制为：

- 文本、代码、键值表、表格、徽标、分隔线。
- 受控的按钮和选择器；事件只能调用清单中登记的扩展动作。按钮文字由宿主根据 `action-id` 查找 manifest 中的 `labelKey`，选择器和选项只返回显式 `label-key`，不能返回面向用户的字面控件文案。
- 宿主只从已经校验的 `locales/<locale>.json` 解析本地化文字键，当前语言缺失时回退默认语言；运行时返回不存在的键会使本次展示失败。不允许远端图片、iframe、任意链接导航和内联样式。

宿主负责转义、主题、焦点、键盘、无障碍、尺寸上限和 React Flow 手势隔离。扩展不得控制节点外部位置、层级或连接线。

被动预览只接收当前画布已经允许渲染的有界正文，最多 20,000 字符或 500 行，单次运行时限 500 毫秒。用户主动触发的处理动作可读取单节点最多 1 MiB 正文，最多处理 64 个用户明确选择的节点，运行时限 30 秒；返回展示和提案合计最多 1 MiB。超过边界必须失败并显示明确原因，不能静默截断后写回正式数据。

## 8. 包格式与隔离运行时

扩展包使用 `.liext` 后缀，内容是确定性 ZIP：

```text
manifest.json
extension.wasm
metadata.schema.json
locales/<locale>.json
checksums.json
signature.ed25519
```

`manifest.json` 至少包含：包格式版本、反向域名扩展 ID、语义版本、扩展 API 主次版本、入口、独立递增且大于零的元数据 Schema 版本、能力和贡献项。扩展 ID 创建后不可更改。清单中的处理器和动作只填写不含点号的包内单段局部 ID，例如 `format-json`；宿主验证后统一生成 `dev.example.json-tools.format-json` 形式的完整 ID。由于局部 ID 只有一段，完整 ID 的最后一段总能无歧义地还原为局部 ID，其余部分总能还原为扩展 ID，不会发生注册表碰撞。扩展不能自行选择或冒用另一个命名空间。WIT 调用中的 `processor-id` 和 `action-id` 始终使用局部 ID；持久化选择项和宿主注册表只使用完整 ID。宿主用元数据 Schema 版本决定是否调用 `migrate-metadata` 以及迁移成功后写入哪个目标版本，不能从扩展包语义版本猜测。

第一版限制：扩展包最多 32 MiB，Wasm 组件最多 16 MiB，清单最多 256 KiB。`checksums.json` 按路径排序记录所有受保护文件的 SHA-256；签名覆盖清单的精确字节。首次安装显示发布者 Ed25519 公钥指纹、包哈希和能力，用户明确选择信任；更新必须使用同一发布者密钥。开发者模式可以安装未签名包，但每次安装或更新都显示不可跳过的警告，不提供后台自动更新或扩展市场。

外部扩展使用 WebAssembly Component Model，接口由版本化 WIT 定义。Rust 后端在独立 `extension-host` 子进程中通过 Wasmtime 执行组件；主 WebView 不加载扩展代码。WIT 用于定义跨语言的结构化接口，组件只能调用宿主显式提供的导入。第一版不向扩展链接通用 WASI 文件、网络、环境、命令行或随机系统接口，只提供本文列出的 Linked Info 宿主能力。

每次调用最多使用 128 MiB 线性内存，并受单内存/实例/表数量、fuel、epoch interruption、输入输出容量和墙钟超时共同限制。独立宿主进程另有 512 MiB 总内存上限，覆盖 Wasmtime 编译器、JIT 代码和 Store 外开销；这两个数字不是同一种限制。被动展示默认 500 ms，主动动作和元数据迁移默认 30 秒；同一个扩展宿主内同时只处理一次调用。每次调用创建新的 Store 和组件实例，崩溃、超时或超限只使本次调用失败。WIT 的纯数据类型直接定义在导出的 `guest` 接口中，宿主不链接通用 WASI，组件声明任何导入都会在实例化前被拒绝。

桌面 Rust 与扩展宿主以逐行 JSON 协议通信，协议版本、请求 ID、授权代次和最大帧长度均在两端复验。桌面进程只从应用同目录或打包资源目录解析固定名称的宿主程序，不从 `PATH` 查找；`.liext` 路径在启动前规范化，包在子进程中重新验证。子进程必须先收到 Hello，之后才读取和编译不可信包，保证 Windows 父进程已经先完成 Job Object 的终止与内存限制；Unix 子进程在读取参数与包之前自行降低地址空间上限。锁定路径和普通调用通道拥有彼此独立的终止权限：Windows 使用关闭即杀死的 Job Object，Unix 使用子进程终止信号。撤销先移除宿主表并立即终止进程，不等待不可信代码返回；迟到结果因进程终止和授权代次双重失效。

第一版普通第三方扩展永远拿不到已标记秘密的原始 payload。桌面 Rust 在 IPC 前再次剥离 `secret`、`totp` 和旧式 TOTP 行，子进程只接收按清单能力裁剪且有容量上限的临时快照。未标记的普通正文仍属于用户明确授权的 `node.read.content` 范围；原始秘密读取若将来存在，必须是独立的受信任官方能力，不能复用普通内容读取权限。

技术依据：

- [Wasmtime 官方文档](https://docs.wasmtime.dev/)
- [WebAssembly Component Model 与 WIT](https://component-model.bytecodealliance.org/design/wit.html)
- [WIT world 的导入/导出边界](https://component-model.bytecodealliance.org/design/worlds.html)

第一份官方 SDK 只支持 Rust，并提供 WIT 绑定、模板、打包、签名和本地测试命令。WIT 契约保持语言中立；JavaScript、Python、Go 等 SDK 只有经过仓库 CI 的真实示例验证后才列为正式支持，不能仅凭工具链能够生成 Wasm 就宣称兼容。

## 9. 工作区与数据生命周期

工作区与导出格式现为 v3。迁移链把 v1 补全为完整空视图，把 v2 的处理器选择保留并补入空的 `extensionMetadata`；迁移后的保存、导出、本机历史、恢复副本和异机密文快照都携带该容器。迁移只增加空容器，不猜测或生成任何扩展数据。

- 删除节点时由核心删除所有扩展在该节点下的元数据。
- 复制、导入和恢复时由核心验证扩展元数据外层节点 ID 全部存在。
- 未安装扩展的元数据仍进入加密、导出和备份。
- 扩展程序、SDK、缓存和编译产物不进入工作区、导出或远端备份。
- 派生缓存进入独立、有容量和可清空的本地缓存，并在锁定工作区时不得持久化明文。
- 整工作区恢复、数据密钥轮换和销毁必须把扩展元数据作为工作区数据处理，不允许形成旁路文件。

TypeScript 与 Rust 使用同一工作区合约夹具校验合法/非法扩展 ID、未知扩展保留、悬空外层节点 ID和 v1/v2 到 v3 的迁移；两端还分别覆盖容量、深度、数值和节点删除清理。扩展自身的 Schema 迁移必须等隔离运行时和安装生命周期具备后通过 `migrate-metadata` 执行，并补充卸载保留和失败迁移回滚用例，不能在数据容器阶段伪造执行结果。

## 10. 实施顺序

1. **契约与包验证器**：建立版本化 WIT、清单、能力枚举、声明式展示和修改提案类型；实现不执行扩展代码的严格包检查器。
2. **工作区元数据**：升级工作区格式，加入命名空间元数据、容量、未知扩展保留、删除清理、v1/v2 到 v3 的确定性迁移及 TypeScript/Rust 共享夹具。
3. **内置适配层**：让现有 Markdown、代码预览或一个新的 JSON 检查器通过新的只读快照、展示模型和元数据存储工作，证明宿主 API 足够，而不是为内置功能保留旁路。
4. **隔离运行时**：实现 Rust `extension-host`、Wasmtime Component Model、能力代理、代次撤销、资源限制和声明式 UI 宿主。
5. **修改提案**：接入差异预览、用户确认、当前 revision 复验、一次历史事务和原子持久化。
6. **安装生命周期**：完成签名/开发者模式安装、启用、停用、升级迁移、卸载保留和显式清除元数据。
7. **开发工具**：发布 Rust SDK、示例、模板、打包/签名/验证命令和独立扩展测试工具。

前一层没有通过合约与故障测试时不得以后面的 UI 掩盖缺口。

当前第 1～3 步已经完成，第 4 步的执行与进程隔离底座已经进入源码并等待 Windows CI 的实际编译与故障测试。独立的 `linked-info-extension-contracts` crate 提供版本化 WIT、严格 Rust 清单类型、能力枚举、声明式展示与修改提案协议，以及只验证、不执行的 `.liext` 包验证器。验证器在读取不可信包时限制压缩与解压容量，拒绝路径穿越、重复/意外文件、未知清单字段、不合法或重复的局部贡献 ID、缺失默认语言文字、越权元数据 Schema、无效 Wasm Component、非规范 SHA-256 清单、弱发布者密钥和无效 Ed25519 签名；完整贡献 ID 只能由宿主加上已验证的扩展命名空间。工作区 v3 已贯通命名空间元数据、旧版本迁移、未知扩展保留、容量与节点生命周期。

第 3 步使用内置 `app.linked-info.json-inspector` 验证同一宿主通道：处理器只取得一次调用有效的临时句柄和按能力裁剪的节点快照，已知 `secret`、`totp` 与旧式 TOTP payload 在调用前剥离；它返回 `code` 与 `select` 声明式元素，不能注入 React、HTML、CSS 或脚本。缩进偏好只保存为该扩展当前节点下的 `{ indentSize: 4 }`，默认两空格不保存冗余记录；写入继续经过工作区通用容量校验、一次历史事务、立即持久化、加密、导出和备份边界。画布和列表共用同一个声明式宿主，列表省略交互控件。输入上限、未知动作、未登记文字键、错误 Schema 和越权元数据均在宿主边界失败关闭。

隔离宿主现在可以对一个已经过验证的包执行 `render`、`invoke` 和 `migrate-metadata`，并覆盖无 WASI、fuel/墙钟超限、代次撤销、进程协议与锁定终止测试；桌面端仍没有把任意包路径暴露为 Tauri 命令。下一步是完成第 4 步的 Windows CI 证据，再进入第 5 步修改提案和第 6 步受管理安装生命周期。不能因为子进程能够执行测试包就宣称第三方扩展已经可安装。

## 11. 完成标准

只有同时满足以下条件，项目才可以在 README 中宣称具有开放扩展框架：

- 一个不在主应用源码树内构建的示例扩展可以打包、安装、启用和停用，无需重新编译主程序。
- 示例扩展能够读取用户明确授权的节点快照、保存有界的专属元数据并返回声明式展示。
- 示例扩展可以提出新增节点或引用，在画布差异预览确认后以一个历史事务提交。
- 未安装、停用、崩溃、超时、升级失败和未知版本都不会损坏节点、引用或扩展元数据。
- 扩展无法获得稳定节点 ID、原始秘密、文件、网络、环境变量、子进程、布局或工作区文件。
- 恶意或错误扩展无法绕过名称唯一、引用端点、工作区 revision、锁定代次、加密、撤销、备份与容量限制。
- Windows CI 覆盖包篡改、能力拒绝、资源超限、锁定终止、迟到结果、元数据迁移回滚和完整安装生命周期。
- SDK 文档能够让新开发者只依赖公开契约完成示例扩展，不能要求读取应用内部 React 或 Rust 实现。
