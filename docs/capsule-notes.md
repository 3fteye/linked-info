# 悬浮胶囊便签与时间画布

## 范围与决定（2026-09-03）

用户确认继续采用推荐行为：胶囊可折叠和展开；失焦或 `Ctrl+Enter` 提交一条记录；普通 Enter 保留为换行；加密工作区锁定时必须先通过主密码或系统快速解锁，再查看或录入内容。外部文档导入扩展、远端同步、脚本执行不在本轮范围。

胶囊是快速录入视图，不增加“便签”领域类型。保存后的记录、日期均为普通正式节点；记录引用当日日期，已有日期按先后建立单向引用，不把同日记录彼此串联。第一次有记录时才建立日期节点，不补齐没有记录的空白日期。

当前实现分成可分别验证的三个切片：

1. 时间画布 v6 契约、旧格式迁移、纯记录事务、撤销/导出/恢复比较和删除清理。
2. Rust 胶囊专属命令隔离与请求中转，主窗口唯一写入所有权、锁定/替换代次和保存成功回执。
3. 独立悬浮胶囊窗口、中英文录入与状态提示、实际失焦/键盘行为，以及合成工作区的桌面回归。

本轮只实施第 1 项；没有窗口或录入入口，不能把数据切片完成描述成便签已经可用。第 2、3 项进入执行前必须一起覆盖下述安全和交互验收。

## 工作区 v6 与正式数据

核心仍是全局 `nodes + references`。`view.timeline` 保存宿主管理的时间画布身份与索引，而非用画布或节点名称识别系统对象：

- `null` 表示尚未建立时间画布。第一次正式记录才创建画布，不修改原有画布及当前活动画布。
- `canvasId` 指向一个现有画布，允许重命名；显示名称必须从本地化资源注入。
- `days` 保存 `date + nodeId`：日期使用 `YYYY-MM-DD`，同一日期只有一个节点，同一节点不能代表两个日期。
- `captures` 保存 `nodeId + capturedAtMs + utcOffsetMinutes + day`。时间为记录提交时系统时刻，偏移为当时 UTC 以东分钟数；日期由二者确定，之后系统时区变化不自动搬动旧记录。
- 索引不能替代正式引用。“记录属于哪天”和“日期相邻”在 `Reference` 中直接可见，跟随工作区加密、撤销、导出、历史和备份。
- 日期索引与记录索引的节点集合不相交。新字段拒绝未知属性、非法日期、悬空 ID、重复日期、重复节点、非整数或越界时间、偏移与日期不一致等数据。

v1–v5 沿既有确定性迁移链进入 v6 并增加 `timeline:null`；旧 v5 仍必须具有 `bookmarks`，不能因为增加 v6 而放松旧格式拒绝规则。v6 存储/导出必须显式包含 `timeline`。无版本的内存快照可以省略空索引，保存边界统一写成 `null`。不把任何设备凭据写入该索引。

## 一次记录的事务

纯函数 `captureTimelineNote` 从当前权威快照准备完整结果，不进行文件操作、取系统时间、读取凭据或直接操作窗口。系统时刻、偏移、请求节点 ID、UUID 分配器和显示文字由调用方显式注入。

一次事务包含记录节点、所需的日期节点、时间画布位置、正式引用以及时间索引。全部校验成功后，由唯一工作区所有者先完成持久化，再更新界面与一次撤销历史；不能把“排队保存”作为成功回执。

- 名称可以为空，正文保持原样；不从正文自动生成标题，以免把密码等内容提升到名称或搜索标签中。名称和正文均为空白时拒绝创建。
- 用户指定的非空名称冲突直接报错。自动生成的日期/画布名称与已有名称冲突时追加数字后缀，不占用或重命名用户已有对象。
- 每个不可变提交预分配稳定节点 ID。失焦、快捷键和丢失回执后的重试使用同一 ID；若当前权威数据已经包含完全相同记录，则返回已有结果，不再创建节点或历史。相同 ID、不同内容或时间必须拒绝。
- 撤销整次记录同时撤销新建日期、引用和位置；不能只删除正文而遗留半个日期结构。

## 布局与用户修改

新日期默认向下追加，当日记录在该日期右侧排列，采用有界尺寸和节点间隔；布局计算只发生在提交边界，不进入指针或逐字输入路径。新记录避让现有位置，不重排旧节点，不改变当前画布或视口。

系统时间回拨或补录时，逻辑日期链仍按日期排序；空间位置采用追加策略，不为插入中间日期而移动用户已经整理的布局。新日期插入逻辑链时，用“前日期 → 新日期 → 后日期”替换原相邻直连；若原直连已被用户删除，则不凭空恢复该旧边。

日期节点和便签仍是普通节点：用户可编辑、移动、移除位置或永久删除。移除日期位置不会因同日再次录入而被自动放回；普通引用删除不会被后台修复。永久删除日期节点时清除该日期和关联记录的时间索引，但不因此永久删除其他记录；它们仍通过普通搜索/画布查找。删除时间画布只清除该画布和时间索引，不删除任何正式节点；再次录入会建立新的时间画布。系统身份不是不可删除的特殊领域实体。

## 悬浮窗口的下一切片边界

主窗口继续持有唯一工作区快照、保存队列和历史。胶囊只持有当前有界录入内容与提交状态，不挂载第二个 `App`、不加载整库、不创建自己的保存队列。Rust 根据真实调用窗口 label 限制胶囊命令，不能仅依赖只为主窗口配置的 capability 推断自定义命令已被隔离。

请求中转必须绑定主所有者会话、工作区替换代次和原始访问 permit；接纳、取出、提交及返回均要复验，不能在迟到提交时重新签发权限。锁定和工作区替换后，旧请求与旧主窗口卸载时的 flush 都不得写入新会话。写入已经成功、只有回执丢失时，不得报告成“未写入”或自动换 ID 再提交。

未正式提交的文字不算已保存。胶囊未解锁时只显示无正文的锁定入口；未提交草稿不能明文落盘或跨锁定保留。锁定失败也不能恢复授权，系统锁定和休眠不能等待悬浮窗口。草稿防丢、关闭主窗口后的驻留和退出行为需要在窗口切片中给出明确提示与测试，不能依赖关机通知补保存，也不能仅凭 UI 隐藏保护秘密。

## 验收分界

数据切片使用合成数据验证：同日复用、跨时区边界、非法 v6 拒绝、v1–v5 迁移、日期插入、名称碰撞、完全重试与冲突重试、旧布局不变、删除清理、导出重载及一次撤销/重做。TypeScript 与 Rust 复用工作区契约夹具；测试和构建只交由 GitHub Actions。

窗口切片还须验证：双重保存触发、保存中锁定、提交后丢失回执、替换后的迟到请求、旧所有者卸载 flush、胶囊调用主窗口敏感命令被拒绝、失败保留当前可编辑草稿、锁定清理正文、退出与收起区别。不得读取真实秘密工作区或通过屏幕截图验收。
