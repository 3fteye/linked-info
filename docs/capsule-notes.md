# 悬浮胶囊便签与时间画布

## 范围与决定（2026-09-03）

用户确认继续采用推荐行为：胶囊可折叠和展开；失焦或 `Ctrl+Enter` 提交一条记录；普通 Enter 保留为换行；加密工作区锁定时必须先通过主密码或系统快速解锁，再查看或录入内容。外部文档导入扩展、远端同步、脚本执行不在本轮范围。

胶囊是快速录入视图，不增加“便签”领域类型。保存后的记录、日期均为普通正式节点；记录引用当日日期，已有日期按先后建立单向引用，不把同日记录彼此串联。第一次有记录时才建立日期节点，不补齐没有记录的空白日期。

当前实现分成可分别验证的三个切片：

1. 时间画布 v6 契约、旧格式迁移、纯记录事务、撤销/导出/恢复比较和删除清理。
2. Rust 胶囊专属命令隔离与请求中转，主窗口唯一写入所有权、锁定/替换代次和保存成功回执。
3. 独立悬浮胶囊窗口、中英文录入与状态提示、实际失焦/键盘行为，以及合成工作区的桌面回归。

代码现已从第 1 项推进到第 2、3 项：接入主窗口所有者会话、Rust 请求中转及独立胶囊界面，并补入合成数据回归。运行时代码 `8150a63` 已通过本轮两项 Windows CI 作业；普通与安全审查结果及一项已有 Edge 测试波动见下方[验证记录](#验证记录)。原生 Windows 悬浮窗口、系统锁定与休眠仍未完成实机验收，不能把自动化通过描述为原生行为已经验证完成。

## 工作区 v6 与正式数据

核心仍是全局 `nodes + references`。`view.timeline` 保存宿主管理的时间画布身份与索引，而非用画布或节点名称识别系统对象：

- `null` 表示尚未建立时间画布。第一次正式记录才创建画布，不修改原有画布及当前活动画布。
- `canvasId` 指向一个现有画布，允许重命名；显示名称必须从本地化资源注入。
- `days` 保存 `date + nodeId`：日期使用 `YYYY-MM-DD`，同一日期只有一个节点，同一节点不能代表两个日期。
- `captures` 保存 `nodeId + capturedAtMs + utcOffsetMinutes + day`。时间为记录提交时系统时刻，偏移为当时 UTC 以东分钟数；日期由二者确定，之后系统时区变化不自动搬动旧记录。
- 索引不能替代正式引用。“记录属于哪天”和“日期相邻”在 `Reference` 中直接可见，跟随工作区加密、撤销、导出、历史和备份。
- 日期索引与记录索引的节点集合不相交。新字段拒绝未知属性、非法日期、悬空 ID、重复日期、重复节点、非整数或越界时间、偏移与日期不一致等数据。

v1–v5 沿既有确定性迁移链进入 v6 并增加 `timeline:null`；旧 v5 仍必须具有 `bookmarks`，不能因为增加 v6 而放松旧格式拒绝规则。v6 存储/导出必须显式包含 `timeline`。无版本的内存快照可以省略空索引，保存边界统一写成 `null`。不把任何设备凭据写入该索引。

## 一次记录的事务

纯函数 `captureTimelineNote` 从当前权威快照准备完整结果，不进行文件操作、取系统时间、读取凭据或直接操作窗口。系统时刻、偏移、请求节点 ID、UUID 分配器和显示文字由调用方显式注入。

一次事务包含记录节点、所需的日期节点、时间画布位置、正式引用以及时间索引。全部校验成功后，由唯一工作区所有者先完成持久化，再更新界面与一次撤销历史；不能把“排队保存”作为成功回执。

- 名称可以为空，正文保持原样；不从正文自动生成标题，以免把密码等内容提升到名称或搜索标签中。名称和正文均为空白时拒绝创建。
- 用户指定的非空名称冲突直接报错。自动生成的日期/画布名称与已有名称冲突时追加数字后缀，不占用或重命名用户已有对象。
- 每个不可变提交预分配稳定节点 ID 和记录时间。失焦、快捷键的重复触发与未修改内容的明确失败重试使用同一身份；若当前权威数据已经包含完全相同记录，则返回已有结果，不再创建节点或历史。相同 ID、不同内容或时间必须拒绝。用户在明确失败后修改内容才建立新提交身份；回执丢失或结果未知时只查询原请求，不自动重提或换 ID。
- 撤销整次记录同时撤销新建日期、引用和位置；不能只删除正文而遗留半个日期结构。

## 布局与用户修改

新日期默认向下追加，当日记录在该日期右侧排列，采用有界尺寸和节点间隔；布局计算只发生在提交边界，不进入指针或逐字输入路径。新记录避让现有位置，不重排旧节点，不改变当前画布或视口。

系统时间回拨或补录时，逻辑日期链仍按日期排序；空间位置采用追加策略，不为插入中间日期而移动用户已经整理的布局。新日期插入逻辑链时，只在原相邻直连仍存在时将其替换为“前日期 → 新日期 → 后日期”；若用户已经删掉原直连，则这两条替换边都不创建，保留原断点，不用间接路径重新接通。

日期节点和便签仍是普通节点：用户可编辑、移动、移除位置或永久删除。移除日期位置不会因同日再次录入而被自动放回；普通引用删除不会被后台修复。永久删除日期节点时清除该日期和关联记录的时间索引，但不因此永久删除其他记录；它们仍通过普通搜索/画布查找。删除时间画布只清除该画布和时间索引，不删除任何正式节点；再次录入会建立新的时间画布。系统身份不是不可删除的特殊领域实体。

## 主所有者与 Rust 请求协议

主窗口继续持有唯一工作区快照、保存队列和历史，是唯一获准提交完整工作区的前端所有者。胶囊只持有当前有界录入内容与提交状态，不挂载第二个 `App`、不加载整库、不创建自己的工作区保存队列。Rust 根据真实调用窗口与 WebView 的 label 共同限制命令，胶囊 capability 仅授予事件监听，不授予文件、导入导出、密码、模型或主所有者命令。

协议字段使用 camelCase；窗口专属入口由 Rust 按真实 label 授权，不信任请求自行声称的窗口身份：

- `open_workspace_owner(requestId, requestSequence)` 返回随机 `ownerId`。主窗口在 `sessionStorage` 只保存无秘密的单调请求序号，重载后继续递增；序号损坏、不可访问或溢出时拒绝打开，不随机回退。Rust 在等待文件操作之前登记高水位并撤销旧 owner/请求；取得文件操作锁后，重新检查请求仍为最新、未取消、原始访问代次有效，才安装 owner。现有读、写与恢复交换命令仍携带捕获的 `ownerId`，旧实例不能重新签发权限。
- `close_workspace_owner(requestId, requestSequence, ownerId?)` 立即取消对应请求，不等待打开回执；取消先到也能阻止之后的旧打开。较旧的打开、取消或卸载不能覆盖新 owner。锁定保留请求高水位，只有进程重启才重置 Rust 计数。
- `set_workspace_owner_ready(ownerId, false)` 暂停接纳、清理待处理请求并轮换 `contextId`；主窗口完成权威加载后才设置为 `true`。锁定、加密边界变化和整工作区替换撤销旧上下文；只有新的合法主会话可以继续工作。
- `inspect_capsule()` 仅返回 `ownerId`、`contextId`、`ready` 与 `encrypted`。`submit_capsule_note(ownerId, contextId, input)` 接收稳定 `nodeId`、名称、正文、提交时间与 UTC 偏移。Rust 名称上限为 512 个 Unicode 字符，正文上限为 100000 个字符，两者 UTF-8 合计不超过 512 KiB；界面可以使用更保守的输入上限。
- Rust 最多保留一条有界请求；`capsule-note-pending` 只通知主窗口，不携带正文。主窗口通过 `take_capsule_note(ownerId)` 取出一次请求，再从唯一权威快照准备完整 v6 事务。已保存的收据只留身份与 SHA-256 指纹，不继续保留正文。同一请求的双重触发不产生第二次提交。
- 主窗口使用 `commit_capsule_note(ownerId, nodeId, contents)` 提交。Rust 在文件操作队列内复验原 owner、context、permit 和访问代次，并核对完整快照中的节点内容及时间索引与原请求相符。只有原子写入确认成功才发布 `saved`；准备或排队完成不算保存成功。拒绝原因限定为 `busy`、`duplicateName`、`empty`、`invalid`、`saveFailed`，不向胶囊转发任意底层错误。
- `inspect_capsule_submission` 返回 `queued`、`processing`、`saved`、`failed` 或 `unknown`。明确未写入的提交错误使用 `capsule_commit_not_saved`；其他提交异常不能被解释成“没有写入”。已落盘但会话已撤销返回 `committedLocked`；目录持久性无法确认或提交结果不确定时返回 `recoveryRequired` 并失败关闭，禁止旧快照继续写入，需真正重启应用进程检查。主窗口通过专属 `restart_application` 执行与退出相同的撤权、秘密剪贴板及模型/扩展清理，再原生重启；胶囊无权调用。仅刷新 WebView、`location.reload()` 或重新签发 owner 均不能解除该进程级恢复屏障。
- `capsule-state-changed` 不携带正文。`capsule_record_activity(ownerId, contextId)` 仅用于真实用户输入，并复验当前请求上下文；状态轮询、动画和保存进度不刷新闲置时间。

锁定先撤销权限并清理请求，不等待胶囊或文件保存队列；已经在旧权限下获准的写入可能完成，但新 owner 必须在文件操作队列之后激活，旧写不能越过新会话。写入已经完成、只有回执丢失时，不能反报未写入，也不能自动换 ID 再创建记录。

### 手动锁定的最后快照

手动“立即锁定”通过主窗口专属 `lock_workspace_with_snapshot(ownerId, contents)` 提交当前完整 v6 快照，不先等待普通自动保存或胶囊 IPC。若胶囊记录已经被主窗口接纳并完成纯事务准备，优先使用该准备结果；尚未提交的胶囊输入框草稿不在这份快照内。

Rust 在“capsule owner 短锁 → 数据密钥短锁”内验证原 owner 和代次，保留只够写这一次快照的原密钥，并设立最终保存屏障。随后立即撤销普通权限、清理秘密剪贴板并通知界面锁定，再等待文件操作队列验证和持久化。只有这个已准入且不可变的快照可以跨过锁定；旧排队保存不能重新获得权限。快照序列化或准入失败也必须锁定，不能为了保存而维持已解锁状态。

| 阶段 / 失败位置 | 持久化与权限 | 界面及恢复 |
| --- | --- | --- |
| 已准入，尚在等待文件队列 | 普通权限已撤销；仅保留一次最终写入授权 | 显示已锁定、正在保存；不提供解锁入口 |
| 替换前失败 | 旧主文件不变，保持锁定 | 明确提示最后修改未保存；允许重新解锁旧主文件 |
| 原子替换及持久性确认成功 | 新主文件为权威结果，清除一次性密钥 | 提示已保存并锁定；显式解锁后重新加载 |
| 已替换但持久性确认失败，或工作线程异常终止 | 不报告未发生；进程级恢复屏障继续阻止打开、解锁及写入 | 要求真正重启应用检查，不允许 WebView 刷新绕过 |

最终保存期间 Rust 同时阻止新 owner、解锁、恢复和密钥替换越过屏障；较早启动的密码或系统验证也必须复验原代次，不能迟到后恢复授权。`workspace_lock_save_started/completed/failed/recovery_required` 均是锁定事件，完成通知本身不重新挂载明文工作区。

Windows 会话锁定、休眠和硬件中断仍不能保证保存尚未送到 Rust 的前端按键；上述最后快照语义针对用户主动手动锁定，不是关机补保存承诺。

未加密工作区显式启用加密或初始化恢复时，主窗口已冻结在独占事务内：Rust 仍立即撤销旧 owner 与胶囊，但不以该次明文撤权提前触发主窗口自动重建会话，而由调用者等待明确事务结果。加密工作区及系统锁定/休眠不使用这个例外。同一有效 owner/context 内下一条请求替换已完成的单槽收据，不会使上一条已经落盘的提交失效；提交后仍以原 owner、访问代次与 context 的有效性判断是否可更新主界面。

## 窗口与草稿生命周期

主窗口通过 `open_capsule_window` 创建或显示固定 `capsule` 窗口，加载独立的 `index.html?capsule` 入口。窗口置顶、无边框、不可自由缩放；收起为 220 × 56，展开为 420 × 360。当前 Windows 路径启用透明原生背景以显示胶囊圆角，其他平台保持不透明回退，不为此启用 macOS 私有 API。展开、收起、拖动、隐藏与聚焦主窗口都通过专属 Rust 命令完成；首版没有托盘驻留，也不让第二个窗口成为工作区所有者。

- 失焦或 `Ctrl+Enter` 提交当前记录；普通 Enter 是换行，输入法组合输入期间不提交。提交期间及结果未知时禁止把正在处理的不可变请求当成另一条可编辑记录。
- 未正式提交的文字不算已保存，只存在当前进程内存；不写入独立明文草稿文件、浏览器存储、日志或远端。收起保留当前草稿并显示未保存提示，不等于保存。界面隐藏按钮在有草稿或请求尚未解决时禁用；原生关闭胶囊窗口只隐藏，不退出应用。
- 明确失败保留当前可编辑草稿；已确认保存后清空输入。锁定、工作区替换和退出清除未提交文字及旧请求上下文，不能依赖关机通知补保存。关闭主窗口仍走正式工作区 flush 后统一退出；写入失败则保留主窗口，不改为后台驻留。
- 加密工作区未解锁时，胶囊仅显示无正文的锁定入口，引导到主窗口使用主密码或系统快速解锁。锁定失败不会恢复授权；界面隐藏也不能替代 Rust 撤权。明文工作区显示未加密提示，不把便签入口描述为秘密存储。
