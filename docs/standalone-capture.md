# 独立明文便签与单向归档

## 当前决定（2026-09-03）

用户明确要求便签从主应用分离，并明确便签不需要加密。本基线替代旧胶囊的“主应用锁定后必须先解锁才能录入”和“草稿只驻内存”规则。旧版已随 PR #16 合并为 `d5e9f19`；其历史验收记录保留，但不作为此次拆分已完成的证据。

- 便签拥有独立可执行程序、应用标识、单实例与退出生命周期。主应用未启动、锁定或退出，不影响便签录入、查看、编辑及重启后恢复。
- 便签名称和正文以明文保存在设备本地，不添加密码、公钥封存或系统快速解锁。主工作区的密码、数据密钥和整库读取能力不能交给便签。
- 归档后的正式节点遵循主工作区现有加密设置；这不追溯保护此前的明文暂存、系统备份或磁盘残留。清理记录不等于安全擦除。
- 节点仍只有名称与内容。日期、便签均为普通节点，时间画布索引仍是现有 v6 视图数据，不新增便签领域类型。

## 本地交接接口

首个跨进程适配器采用同一操作系统用户目录内的版本化 SQLite 收件箱。两个程序通过独立 Rust crate 的有界接口通信，不互相读写对方任意文件，不开放 HTTP 端口，也不把数据库句柄交给 WebView。共享的是交接契约和存储适配器，不是主应用的生命周期或工作区权限。

收件箱位于独立便签应用目录，草稿、待归档正文及短状态为明文。它不进入主工作区导出或远端备份，不含主工作区密码、密钥、其他节点正文或秘密。文件按当前用户权限创建；相同系统用户下的恶意程序可以访问明文便签，这不属于主工作区加密承诺。双方仍严格校验版本、UUID、容量、状态与参数，不能把本地文件当作可信工作区快照。

第一版只面向这台设备当前主应用的一个工作区。主应用只在有效 owner、解锁、权威快照已加载且没有其他独占事务时顺序接纳记录；不自动解锁、不启动云服务、不做双向同步，也不新增开机自启。

## 记录与状态

每条记录具有稳定 ID、递增修订号、名称、正文及提交时的系统时间/UTC 偏移。归档按原记录日期，而不是主应用解锁日期。默认最多 1000 条未归档记录、64 MiB 正文总量；单条沿用名称 512 字符、正文 100000 字符及合计 512 KiB UTF-8 的限制。

| 状态 | 便签行为 | 主应用行为 |
| --- | --- | --- |
| 草稿 | 本地保存，可查看编辑；收起和退出不丢弃已确认落盘内容 | 不归档未提交草稿 |
| 待归档 | 显示本地已保存；编辑前原子退回草稿 | 解锁后按顺序领取 |
| 已领取 / 提交中 | 当前条目只读，仍可创建和编辑其他草稿 | 使用固定修订快照准备完整时间画布事务 |
| 失败 | 保留正文与可读原因；用户可修正、重新提交 | 不因名称冲突或非法输入覆盖已有节点 |
| 结果待确认 | 保留正文，不自动换 ID 重投或允许修改在途快照 | 恢复时核对主文件和提交记录后决定确认或重试 |
| 已归档 | 只有持久化确认后才移出正文列表 | 保存成功后确认；只保留最小去重收据，不保留正文 |

普通 Enter 换行，Ctrl+Enter 或离开录入区提交。输入中的草稿先写本地；“本地已保存”和“已归档主工作区”必须使用不同反馈。编辑与领取用修订号和数据库事务排序，不能让旧自动保存或旧回执删除新修改。

## 提交点与失败恢复

现有时间画布准备事务、原 owner/permit 复验与提交感知原子文件写继续复用。记录、日期、引用、布局和索引一起成为正式工作区的一次事务；保存确认前不能清除收件箱正文。

| 失败位置 | 正式工作区 | 收件箱与恢复要求 |
| --- | --- | --- |
| 领取前或准备校验失败 | 不改变 | 保留待归档或明确失败记录 |
| 主文件替换前失败 | 保留旧主文件 | 允许同一身份重试，不产生部分节点 |
| 主文件已提交，确认回执尚未写入 | 新主文件可能已含记录 | 以固定 ID、原记录快照及提交记录复核，不盲目再次创建 |
| 已替换但持久性不确定 | 失败关闭，禁止旧 React 快照回写 | 保留正文和待确认状态，重启/解锁后再核对 |
| 确认已归档后用户删除节点或恢复旧备份 | 遵循普通删除/恢复语义 | 最小持久收据阻止已消费记录被自动重新导入 |

归档提交必须有跨进程、跨重启的持久化领取与确认边界，不能沿用旧胶囊仅内存单槽回执。原文件与候选文件的提交校验信息只用于恢复；不能把整份主工作区或可解密副本写进便签目录。遇到无法证明结果的文件替换，不自动认定成功或失败。

锁定仍先撤销主工作区权限。便签数据不随之清空；未提交或未获准的归档保留在收件箱。已经获准的正式写入按原提交语义处理，迟到回执只能确认对应的固定修订。便签输入和归档轮询不延长主应用闲置解锁时间。

## 实施与验证切片

1. 版本化收件箱、限额、编辑/领取排序、收据和崩溃恢复测试；文档先于实现。
2. 主应用解锁后顺序归档及旧进程内胶囊入口替换，保留工作区单一写入和历史事务。
3. 独立便签程序和界面、明确保存反馈、打包与独立生命周期回归。

全部自动测试、构建、格式和审计由 GitHub Actions 执行，只使用合成数据。验收要覆盖主应用未运行时录入、便签重启恢复、主应用锁定时继续录入、解锁后按原时间归档、重复回执、领取/编辑竞争、名称冲突、提交中锁定和两个应用分别退出。不得读取真实工作区或用截图验收；本轮没有自动合并或更新本机安装的授权。

## 发布组成

Windows 便携包包含 `linked-info-desktop.exe`、`linked-info-capture.exe`、`linked-info-extension-host.exe`，便签无须先启动主程序。主程序只启动同目录固定便签可执行文件，不接受用户输入的可执行路径或 shell 命令。两个应用具有不同单实例标识。

固定入口更新脚本必须校验全部三个可执行文件及非空本地 LLM runtime，不能只验证主 EXE 后沿用另一版便签。新脚本明确拒绝缺少便签的旧两程序包，不为旧胶囊增加迁移或运行兼容路径。已有主工作区仍使用 v6；独立收件箱是新的 v1 文件，不从旧应用或用户文件中猜测和导入草稿。

当前分支处于实现与 CI 验证阶段，旧 PR #16 的通过结果不计入本次验收。发布包验证、两条云端审查及独立进程实测收口后再请求合并，不在本轮自动替换用户运行版本。
